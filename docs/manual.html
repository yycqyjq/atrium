中庭使用手册

一个中心，五间房：书房读、画廊看、工具房用、工坊试、陈列廊造。数据存你自己的 GitHub 仓库，桌面与网页同一份内容。这本手册讲怎么日常使用、怎么配置、出了问题去哪查。

v1.2.12 · 2026-09-16 · 适用 release/mac-arm64 与后续版本

01

开始使用

桌面端是日常入口。打开 ~/Desktop/atrium/release/mac-arm64/中庭.app，首次启动会解压内置服务到系统数据目录，随后窗口直接打开中庭。之后每天双击即用。

本机开发模式（改代码时用）：

pnpm build        # 构建 standalone 产物
pnpm desktop:cert # 打开桌面窗口（含证书注入）
pnpm desktop:smoke # 自检：全链路验证后自动退出
pnpm smoke        # 冒烟巡检：六房 + 接口逐项体检

重新打包（改完代码想要新 App）：

pnpm desktop:pack # 打包 .app
pnpm desktop:dist # 额外产出 dmg
快捷键：⌘1–5 切换五个房间；⌘N 直达写作台；⌘K（或侧边栏「搜索」）唤起全局搜索，一搜直达文章、展品与书签；房间内的搜索框按 / 聚焦。
02

五间房

读 · READ

书房

文章列表与阅读页。顶部搜索框即时过滤标题、摘要、标签、目录；每篇文章右上角有「编辑」直达写作台。

看 · VIEW

画廊

图片按相册（子目录）逐卷铺开，右侧楼层目录可跳转；顶部搜索框即时筛选图片名或相册；图片随滚动懒加载，每张图上方标注文件名与日期。点缩略图开灯箱：← → 可跨相册连续翻页、Esc 关闭、可分享单张深链（/gallery?album=ark&view=3）。有令牌时可拖拽直传图片（目标相册用下拉选择或直接输入新相册名）；卡片悬停右下角浮出编辑 / 移除（与工具房同款：编辑走弹层、移除原位确认、结果轻提示），灯箱里也能重命名。

用 · USE

工具房

书签墙，按分类分组，即时搜索；站点图标随滚动懒加载。有令牌时：添加与编辑共用同一弹层表单（粘贴网址自动带回标题、描述与站点图标）；卡片悬停右下角浮出编辑 / 移除，移除在原卡片上原位确认（高度不跳动）；结果以底部轻提示反馈——全部与旧版 tools.json 格式兼容。

试 · TRY

工坊

接入你自己的组件仓库（可多个），取件后在页面内现场渲染；按分组分区 + 楼层目录 + 即时搜索，卡片带来源与「最近更新」徽标。每件展品带用法、属性与源码视图，深色主题自动适配。也能挂线上站点。在设置页「组件项目」里增删（仓库填名字即可，自动用当前账号）。

造 · MAKE

陈列廊

设计系统活文档：色板、排印、组件、空态。想做新页面时先来这里取件；深浅双主题实时切换，右上角可切「默认 / 紧凑」两种密度。

03

写作：从一句话到一篇文章

书房标题旁点「写作台」（或按 ⌘N）。填标题（文件名自动取标题，实时预览）与正文（Markdown），可选填「参考资源」（每行一个，保存时自动附到文末）。点「发布到仓库」：

  1. 1正文连同 front-matter 以 Markdown 写入内容仓库根目录，成为一次规范提交（如「新增《文章标题》」）。
  2. 2书房列表立刻出现这篇；点开就是排版好的阅读页（锚点、代码高亮、目录齐备）。
  3. 3要改？文章页点「编辑」：标题与文件名自动识别、参考资源自动提取为可编辑列表，全文回填；要删？编辑态底部「删除这篇文章」，二次确认后移除。
回溯：所有写操作都是 GitHub 提交，仓库历史里随时可以查看或回滚任何一次改动。
04

图片：直传图床

画廊页顶部的上传区支持拖拽或点选多张，上传前可选目标相册（相册 = 图床仓库的子目录）。单张不超过 20MB；重名文件自动加时间戳，永不覆盖已有图片。

上传完成刷新即见。画廊图片走 jsDelivr 线路加载，失败自动切回 GitHub raw 兜底——网络波动不需要你操心。刚上传的新图偶尔几分钟内缩略图未更新，是 CDN 缓存，稍后自愈。

05

连接仓库（登录）

中庭的「登录」= 连接你的 GitHub 仓库。侧边栏左下角的头像就是入口：未连接时显示虚线方块与「连接仓库」，已连接时显示用户名。

  1. 1点击左下角用户条（或其旁的齿轮图标），进入设置页。
  2. 2填写 GitHub 用户名、内容仓库名（文章与书签所在）、分支，以及访问令牌（生成入口见页内链接，勾选 repo 权限即可）。
  3. 3可选：填画廊仓库名与目录（独立图床时）。不填则画廊跟随内容仓库。
  4. 4点「保存并连接」，书房、画廊、工具房、写作台与工坊立即点亮。
安全：令牌只保存在本机配置文件（权限 600），页面里只写不显；线上部署的站点对访客默认只读。
06

配置参考

配置有两处：data/config.json（桌面端在系统数据目录 ~/Library/Application Support/atrium-desktop/data/）与环境变量。环境变量优先。

作用变量 / 字段
内容仓库GITHUB_OWNER GITHUB_REPO GITHUB_BRANCH GITHUB_TOKEN
画廊仓库galleryRepo 字段或 GITHUB_GALLERY_* 变量（缺省跟随主仓库）
画廊目录galleryDir 字段或 ATRIUM_GALLERY_DIR（空串 = 仓库根）
组件项目demoProjects 字段或 ATRIUM_DEMO_PROJECTS（JSON 数组；仓库读 atrium.json 清单，取件渲染）
工具清单ATRIUM_TOOLS_FILE（缺省 admin/tools.json；/ 或 ./ 开头读本地文件）
备选内容源GITEE_* 同款四件套 + ATRIUM_DEFAULT_PROVIDER=gitee
站点域名NEXT_PUBLIC_SITE_URL（部署时设，RSS/sitemap 用）
写开关ATRIUM_ALLOW_WRITE=1（本地与桌面自动注入；线上默认只读）

config.json 示例（桌面端已写好，token 为你的 GitHub 令牌）：

{
  "defaultProvider": "github",
  "repos": { "github": { "owner": "yycqyjq", "repo": "ark-notes", "branch": "main", "token": "…" } },
  "galleryRepo": { "owner": "yycqyjq", "repo": "ark-images", "branch": "main" },
  "galleryDir": "",
  "demoProjects": [
    { "id": "bricks", "name": "砖瓦", "kind": "repo", "repo": "yycqyjq/bricks", "branch": "main" }
  ]
}
07

部署到 Vercel

  1. 1打开 vercel.com/new，GitHub 登录，Import「atrium」。
  2. 2环境变量填：GITHUB_OWNER=yycqyjq、GITHUB_REPO=ark-notes、GITHUB_TOKEN=你的令牌（建议加 GITHUB_GALLERY_REPO=ark-images）。
  3. 3点 Deploy，一分钟出网址。
  4. 4部署后把 NEXT_PUBLIC_SITE_URL 设为正式域名并 Redeploy，RSS 与 sitemap 链接即指向正式地址。
安全边界：线上部署默认只读——写接口全部 403，访客无法改动你的仓库。这是机制保证，不依赖任何人记得配置。
08

故障排查

现象原因与处理
写作台/添加工具/上传入口不见了未连接仓库。点侧边栏左下角「连接仓库」，配好令牌后入口全部出现。
画廊空但书房有文章画廊仓库指向未配置（跟随了内容仓库）。在连接页填画廊仓库名，或配置文件写 galleryRepo。
书房 / 工具房空检查 config.json 的仓库指向与令牌；/api/providers 返回 configured:true 即接入正常。
画廊图片偶发破图jsDelivr 对新文件有缓存延迟（数小时），会自动恢复；也可稍后刷新触发 raw 兜底。
写作 / 上传 403本地出现即说明启动脚本未注入开关（正常不会发生）；线上 403 是设计行为。
保存提示「sha 过期」仓库端在你编辑期间有新改动，刷新页面后重试即可。
额度 403 / 限流匿名限额 60 次/小时；配 GITHUB_TOKEN 后为 5000 次/小时。
App 无法打开本机构建无隔离属性，正常双击即用；若经 AirDrop 等渠道传输，右键 → 打开一次即可。
数据目录在哪~/Library/Application Support/atrium-desktop/（server 服务、data 配置、certs 证书）。
