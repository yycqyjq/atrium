RENAME & RESTRUCTURE PROPOSAL · V1

从「管理后台」，
回到「自己的空间」

ARK Admin 是一套以 GitHub 为唯一持久层的个人中枢：博客、图库、工具、趋势与组件陈列共居一室。它的问题不在工程质量——而在身份：名字叫 Admin，长相是管理后台，但产品的实质是一个人的数字空间。本提案回答两件事：它该叫什么名字，以及如何重构才能让名字落地。

01

现状速写

先说结论：这个项目的底子相当好。pnpm monorepo、前后端分离、Electron 桌面端、Playwright 端到端测试、commitlint 提交规范——工程骨架是一个认真维护的项目该有的样子。真正的问题集中在表达层：它把自己打扮成了一个「后台」。

架构上，GitHub 仓库承担了数据库、CDN 与 CMS 三重角色：文章是仓库里的 Markdown，图片是仓库里的资源，工具书签是仓库里的 tools.json。本地 Koa 服务只做三件事——保管 Token、代理请求、聚合缓存。这是一套自洽且低成本的个人架构，值得原封不动地保留。

模块 现有能力 数据源
博客 Markdown 渲染、代码高亮、目录树、文章 TOC、图片迁移（detail / DirTree / MarkdownRenderer / TableOfContents） GitHub 仓库
图库 图片上传 / 删除、目录管理、EXIF 解析、缓存加载（Gallery / CachedImage / exifr） GitHub 仓库
工具集 动态书签、分组、站点标题识别（Portfolio / Bookmarks / identify 接口） GitHub 仓库 tools.json
GitHub 趋势 热门项目浏览、按语言 / 话题筛选（GitHubTrending，挂在 Portfolio 下） GitHub Trending
组件陈列 组件 demo 与功能示例、热力图等（Components / DemoRenderer / AMapHeatmap） 本地内置
账号与设置 登录、GitHub Token 安全链路、站点名 / 主题配置（Login / auth / SettingsModal / ThemeToggle） 本地后端

平台资产另有：Koa 后端（Token 代理、OpenAPI、坐标反查）、Electron 壳、Playwright e2e、docker-compose 与 devcontainer。

核心矛盾：名字叫 Admin、导航是后台菜单、视觉是组件库默认皮肤——内容像被「管理」，而不是被「居住」。

这不是丑的问题，是没有身份的问题。
02

命名提案

起名的依据不是好听，而是：名字能不能给重构后的信息架构一个心智模型。以下四个方向分属不同气质家族，各自附带隐喻、理由与视觉联想。

中庭
Zhōng Tíng · Atrium
提案推荐

家的中心天井——所有房间围绕它展开，光从顶部进来。GitHub 是地基，应用是这座房子的中庭。

  • 它直接命名了重构方向：从「管理后台」变成「有房间的家」。博客是书房、图库是画廊、工具是工具房、组件是陈列廊，中庭把它们聚在一起——导航结构天然成立。
  • 架构语义准确：所有数据从 GitHub 汇入这个中心再分发到各房间，「中庭」就是这套数据流的形状。
  • 可扩展：未来加新模块等于加新房间，心智模型不会崩；对外展示时也撑得起「个人站点」的身份。
视觉联想 回字框 天井俯视图 气质 沉稳 建筑感 家的秩序
自留地
Zì Liú Dì · Homestead

互联网上属于你的一小块地——种什么、什么时候收，全由你自己定。

  • 天然共鸣：中文开发者圈早已用「数字自留地」形容个人站点，这个名字自带归属感，一听就懂。
  • 隐喻与 GitHub 相配：仓库是田，文章是庄稼，工具是农具——「耕耘」的语义和这套架构严丝合缝。
  • 有烟火气：个人项目不端着，随性生长，很有「自己的地盘」的松弛感。
视觉联想 田垄线 一株苗 气质 温暖 随性 生长感
注意：气质偏田园、偏私享。如果未来想往「专业作品集、对外展示」的方向走，这个名字会显得软一些。
码头
Mǎ Tóu · Wharf

GitHub 是货仓和船队，这里是你的私人码头——内容装卸、中转、再出发。

  • 技术隐喻最准确：整套架构就是「内容从 GitHub 仓库流入本地应用」，码头命名了这条数据水路。
  • 有枢纽的动感：汇聚与出发，适合强调「一切从这里进出」的中心感。
  • 英文友好：Wharf 简短好记，域名、仓库名、npm 包名都干净。
视觉联想 缆桩俯视 吊臂线稿 气质 硬朗 工业感 枢纽
注意：「码头」是功能视角的名字，情感浓度偏低——它像一件趁手的工具，而不是一个家。
工坊
Gōng Fāng · Atelier

手艺人的工作室——写文章、做工具、攒组件，都是你的手艺。

  • Maker 视角：产出物（文章 / 工具 / 组件）在这个名字下都是「作品」，与开发者的身份最契合。
  • 组件陈列最顺：demo 区在工坊隐喻里就是「成品架」，语义自然。
  • Atelier 有格调：法语里艺术家工作室的词，中英双名都拿得出手。
视觉联想 工作台俯视 刻刀木纹 气质 手作 匠心 专业
注意：「坊」字近几年被各类工作坊用得略多，独特性在四个候选里最弱。

推荐「中庭」。理由只有一条但足够硬：这次重构的核心命题是「让内容有主人感」，而「中庭」不止是个名字——它直接给了重构后的信息架构一个可以落地的空间隐喻（中庭 + 四厢，见第 04 节）。其他三个名字都很好，但它们描述的是这个项目的某个侧面；「中庭」描述的是它重构之后想要成为的样子。

03

重构边界

重构不是推倒重来。先划清哪些东西动不得、哪些放开手改，才不会越改越散。

必须保留

  • GitHub 存储架构——仓库即数据库 / CDN / CMS，这是项目的灵魂
  • 五大模块既有功能——博客、图库、工具、趋势、组件，一个不减
  • Token 安全链路——后端代理、不落前端
  • Electron 桌面端与 pnpm monorepo 结构
  • 登录与配置体系——含 siteName 降级链

放开重构

  • 信息架构——导航分区、模块归属、路由命名
  • 视觉系统——tokens、主题、字体、组件密度
  • 首页形态——从功能列表改为个人主页
  • 导航形态——顶栏 / 侧栏 / 命令面板的选型
  • 文案与命名——项目名、页面标题、空态文案

平庸之源

  • Admin 心智——名字、布局、语气都在说「后台」，而不是「我的空间」
  • 默认皮肤——AntD 默认蓝 + 默认样式，没有任何属于这个项目的识别度
  • 平铺导航——六个一级菜单等权重排列，没有主次与叙事
04

三阶段路线

顺序刻意安排为「先立身份、再换皮肤、最后磨细节」——名字和骨架定了，视觉才有落点；视觉定了，细节才不白磨。以「中庭」为例，新的信息架构如下：

现状 新归属（以「中庭」为例）
首页（文章 + 工具杂烩）中庭 · 个人主页——身份、近期文章、常用工具、快速入口
博客书房 · 读——文章与长内容
GitHub 趋势（现挂 Portfolio）书房 · 读——并入，作为「在读 / 风向」
图库画廊 · 看——图片与影像
照片查看器（现挂 Portfolio）画廊 · 看——并入
工具集 + 书签工具房 · 用——工具、书签、外链
组件陈列陈列廊 · 造——组件 demo 与实验
关于廊下 · 简页

分区词汇随最终选定的名字调整：自留地 → 田垄，码头 → 泊位，工坊 → 工位。结构不变，只有措辞随名。

APHASE A

定位与骨架

把名字落进代码，把导航从「六个等权菜单」重组为「一个中心 + 四个分区」。

  • 全链路改名——仓库名、package name、站点标题默认链（siteName → username → 兜底名）一次换净，不留 admin 残留
  • 导航与路由重组——按上表迁移模块归属；GitHub 趋势、照片查看器各归其位
  • 首页改为个人主页——回答「这是谁的空间」：身份区 + 近期文章 + 常用工具 + 快速入口

产出：新信息架构 + 新导航 + 改名提交

BPHASE B

视觉系统

从组件库默认皮肤，换成属于这个名字的一套 tokens。

  • 建立设计 tokens——主色系（与名字气质匹配）、字体层级（标题 / 正文 / 代码）、间距与圆角刻度
  • 亮暗双主题重调——现状是变量简单反转；重做暗色的层级、对比度与边框透明度
  • 导航形态升级——顶栏改为侧栏工作台，或顶栏 + 命令面板（⌘K 快速跳转，很配「个人中枢」的定位）

产出：tokens 文件 + 双主题 + 导航改造

CPHASE C

体验细节

骨架和皮肤立住之后，把每个房间的细节磨到位。

  • 三态统一——Loading / Empty / Error 全站一套规范（现有组件基础好，缺的是空态设计）
  • 移动端审计——现有 768px 断点较基础，逐页过手机宽度
  • 性能与手感——图片懒加载补全、路由过渡、设置与登录的微文案

产出：状态规范 + 移动端全过

05

第一刀建议

不要大爆炸式重构。建议第一刀只切一个纵切面：新首页 + 新导航 + 核心 tokens，一次提交立住方向。切完之后，方向对不对一眼可见，后续每个模块按新骨架逐个迁移即可，随时可以停在一个可用的状态上。

  • 名字、站点标题、导航语义、登录后首屏一次对齐，全站无 admin 残留
  • 新首页能一眼回答「这是谁的空间」——身份、近期内容、常用入口
  • 主色、字体、间距、圆角来自 tokens 文件，不再来自组件库默认值
  • 暗色模式是重新调过的第二套层级，不是简单反色
  • 桌面与手机宽度各过一遍首页与一个内容页，布局不塌
